# JSON Schema

This document defines the normalized song JSON contract between the Python pipeline and Blender.

The repository currently has V2 lesson JSON fixtures in `data/lesson_tests/`. Keep those working. Use this document as the target contract when normalizing MIDI-derived song data for Blender.

## Contract Rules

- JSON is produced by the Python pipeline.
- JSON is consumed by Blender.
- JSON must preserve tick-based timing and seconds-based timing.
- Blender may convert seconds to frames.
- Blender must not calculate beats, measures, tempo maps, or tick-to-seconds timing.
- Field names should remain stable once Blender depends on them.

## Top-Level Shape

```json
{
  "schema_version": "1.0",
  "song": {},
  "timing": {},
  "tracks": [],
  "notes": [],
  "measures": [],
  "beats": [],
  "audio": {},
  "guitar": {}
}
```

## Required Sections

### `song`

General song metadata.

Expected fields:

- `title`
- `source_midi`
- `source_wav`
- `duration_seconds`

### `timing`

Global timing data.

Expected fields:

- `ppq`
- `tempo_changes`
- `time_signature_changes`

Each tempo change should include:

- `tick`
- `seconds`
- `bpm` or `microseconds_per_quarter`

Each time-signature change should include:

- `tick`
- `seconds`
- `numerator`
- `denominator`

### `tracks`

MIDI track metadata.

Expected fields:

- `id`
- `name`
- `channel` when available
- `instrument` when available

### `notes`

Analyzed note timing and pitch data.

Each note should include:

- `id`
- `track_id`
- `pitch`
- `start_tick`
- `end_tick`
- `duration_ticks`
- `start_seconds`
- `end_seconds`
- `duration_seconds`
- `start_beat`
- `end_beat`
- `measure`

Velocity may be included as a raw MIDI fact if available, but V1 does not interpret velocity.

### `measures`

Measure boundary data generated by the Music Analyzer.

Each measure should include:

- `number`
- `start_tick`
- `end_tick`
- `start_seconds`
- `end_seconds`
- `time_signature`

### `beats`

Beat position data generated by the Music Analyzer.

Each beat should include:

- `index`
- `measure`
- `beat_in_measure`
- `tick`
- `seconds`

### `audio`

Final WAV sync data.

Expected fields:

- `file`
- `audio_offset`

`audio_offset` is measured in seconds. Positive values delay the WAV relative to visual timing. Negative values start the WAV earlier relative to visual timing.

### `guitar`

Guitar-specific mapping data.

Expected fields:

- `tuning`
- `strings`
- Per-note mapping references, either embedded in `notes` or stored in a dedicated mapping table.

Each mapped note should include:

- `string`
- `fret`

## Lesson V2 Tempo

Lesson V2 JSON (what the dashboard sends to Blender) is beat-based. Its timing fields are:

- `tempo_bpm`: tempo from beat 0.
- `tempo_changes` (optional): `[{"beat": "24", "bpm": 111}]`, beats strictly increasing and after 0; each tempo holds until the next change.

Seconds come only from `tempo_map` / `seconds_at` / `beat_at` in `guitar_video_app/core/lesson_v2.py`; Blender and the MIDI export call these rather than dividing by one tempo.
